## How this audit was done

Five parallel domain audits (security, DB/concurrency, frontend, Excel+KPI, deploy/runtime), plus a lead pass, against a **throwaway stack running the same image bytes** as production-test (`mesflow-app:71.0.0.310` + `postgres:17-alpine`). Findings were reproduced wherever a reproduction was possible; anything not reproduced is labelled accordingly.

**Confidence is used strictly:**

- **CONFIRMED** — demonstrated by running it, with the command and its output recorded.
- **HIGH-RISK SUSPECT** — the code path is unambiguous but the end-to-end behaviour was not executed.
- **TECH DEBT** — real, not currently harmful.

Every P0 and the most serious P1s were **re-verified personally by the lead auditor** rather than accepted from a sub-audit. That verification changed two results — see *Corrections* below — which is the reason it was done.

**One live-host rule was applied throughout:** the unauthenticated write surface was proven exploitable **only on the local stack**. Against `mesflow.net` nothing but harmless read probes were sent (e.g. `POST /api/kiosk-web/scan {}` → `400 SCN-001`), which establishes reachability without writing a byte of real data.

## Corrections made during verification

Two sub-audit findings did not survive checking, and are recorded here rather than quietly dropped:

1. **SEC-08** (a `viewer` can export any PO's router workbook) — predicted from a static reading of `_permission_for_request()`. Tested with a real viewer session: **403**, not 200. It fails only because `viewer` does not actually hold `po.view` in the seeded RBAC (see **RBAC-01**). The mechanism is real, the exploit is not currently reachable. Downgraded P1 CONFIRMED → **P2 HIGH-RISK SUSPECT**.
2. **SEC-06** (public workforce productivity dump) — the endpoint *is* public and unauthenticated on the live host, but it currently returns `employees: []`. Real exposure, currently zero rows. Severity kept, live impact stated honestly.

Similarly, **OPS-12** (a `MESFLOW_ENV` typo disables the secret-key guard) is confirmed reproducible but **latent** — every real deployment path uses exact lowercase `production`, and the live host reports `environment='production'`.

## What was verified as SOUND

An audit that only lists defects misrepresents the system. These were actively attacked and held:

**Concurrency and idempotency on the work-session write path — genuinely well built.** Under 20-way concurrent load (136 write requests):

- 8 simultaneous starts for one employee across 8 operations → exactly **1** row (`uq_open_session_per_employee` partial unique index + `23505` → `ConflictError`), 7 clean 409s.
- 8 simultaneous identical `request_id`s → 1 insert, 7 replays, 1 DB row (`pg_advisory_xact_lock` serializes before the read).
- 6 simultaneous finishes of one session with different `request_id`s → 1 × 200, 5 × 409, exactly 1 `quantity_movements` row. No TOCTOU window.
- **Zero deadlocks** (`grep -ci deadlock` on the Postgres log → 0). `lock_production_order_for_operation_first()` holds across start, finish, adjust, edit, transfer, auto-close and rework-resolve.

**Migration graph is clean.** One head, no branches, and four independent live-vs-migration comparisons (tables, all 791 columns, named indexes, CHECK constraints) found **zero drift**.

**Startup fails closed.** A container pointed at a DB stamped with a bogus revision exited 255 without ever serving a request.

**No SQL injection.** Every f-string/`.format()`/concatenation into SQL was traced. Dynamic fragments come from validated `frozenset` catalogues (`domain/policy.py`) or module constants; WHERE clauses use `%s` with parallel params; ORDER BY is whitelisted; LIMIT/OFFSET are `int()`-clamped; identifiers use `psycopg.sql.Identifier`.

**Upload validation is correct.** Extension allowlist, explicit deny of active types (`.svg/.html/.js`), magic-byte verification, per-type size caps, server-generated stored filenames, and `send_from_directory`/`.resolve()`+`relative_to()` on every serve path. No traversal. (The upload *authorization* gap is SEC-09 — a different problem.)

**Passwords are correctly redacted** from `action_logs` (verified on the wire); the badge-QR gap next to it was the real leak, now fixed.

**Session revocation genuinely works.** `auth_epoch` HMAC-binds the cookie to `password_hash|active|session_epoch` with `hmac.compare_digest`; logout bumps `users.session_epoch`, invalidating across devices.

**No reachable divide-by-zero** anywhere in Python or SQL — every division is `NULLIF`-guarded, inside a lazily-evaluated `CASE`, or behind a `HAVING`.

**`time_policy.py` is well built** — every entry point raises on naive datetimes. The timezone bugs found are all in code paths that *bypass* it.

**Zero TODO/FIXME/HACK/XXX markers** in `app/`. Of 175 `except Exception` handlers, only 5 swallow silently and 4 of those are documented deliberate best-effort paths.

**Syntax integrity is clean**: `compileall` over `app scripts tests` exits 0; `node --check` over 99 JS files reports no errors.
